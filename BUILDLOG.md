# Build log

## 2026-07-25 — the forward flow: chat, and the airtime queue made visible

**Tried:** Everything so far pointed one way — the node talks, the app listens. This session opened the other direction. Chat is the first user of it, and it is now wired end to end against the mock.

**Protocol (`proto 2`).** Positions stay binary 32-byte records; everything else is one JSON object per text frame, *both ways*. Node → client: `hello` (now carrying `you:{id,name}`, `cap`, `duty`), `roster`, `chat`, `queued`, `relayed`, `rejected`. Client → node: `send {msgId,text,lane}`, `name`, `cursor`, `reset`. JSON until Phase 05 by decision (§6) — protobuf arrives with codegen, not before.

**Mock node** gained `src/chat.js` (the one shared channel, node-assigned `seq`, per-cursor backfill, admission validation) and `src/relay.js` (the interesting one): priority lanes, deficit round-robin across clients with credit that decays rather than banks, a per-client depth ceiling that refuses with a reason, and 1% duty-cycle enforcement. Pure logic, `now` passed in, no sockets — so the whole thing is unit-testable in microseconds. `plan()` and `tick()` share one service loop, which is deliberate: **the reason shown to a sender is computed from the same order the queue actually transmits in**, so the UI cannot drift from the scheduler. 16 mock tests green, 15 Kotlin (10 of them new `ControlTest` cases parsing frame strings copied verbatim out of `server.js` — the same cross-implementation trick the golden vectors play, applied to the control path).

**App**: `Control.kt` in `:protocol` (hand-parsed off a `JsonObject`, so an unknown `type` from a newer node becomes a renderable `Unknown` rather than an exception that kills the socket); `NodeClient` can now send; `LiveViewModel` holds messages/roster/self-identity and reconciles the optimistic bubble with the node's echo by `msgId`; Chat tab rebuilt from wireframe stubs into the real thing, with a text field, a Send and an Emergency (lane 0) button, and a live "link out" panel. Clients tab now shows the real roster. `:app:compileDebugKotlin` green.

**Surprised — twice, both about honesty:**

1. **Chat between phones on this node never touches LoRa.** They share a WiFi/BLE link; the radio is the link *out*. The wireframe's "queued 40 s" implied everything waits for airtime, which would have been a lie about local delivery. So the app now shows two truths per message and never conflates them: *delivered* (node echoed a seq — everyone here has it, immediately) and *relay* (the same message queued for LoRa). Every position already carries its uncertainty; every message now carries its delivery state the same way.
2. **The first queue reasons lied.** An emergency message printed "emergency — going out now" while its own eta said 66 s — nothing was ahead of it, but the radio was still locked out from the previous transmission. Nothing was ahead, so nothing got named, so the countdown had no cause attached. Fixed to name the actual constraint: `queued 67 s — radio duty-cycled`, `emergency — first in line, 66 s of duty-cycle lockout`. A test now asserts a reason never claims "now" while the radio is down. This is exactly the §6 rule biting one level deeper than expected: a reason that omits *why* is just a spinner with a number on it.

**Also worth banking:** at a real 1% duty cycle, one 26-byte message costs 558 ms of airtime and locks the radio for ~56 s. Three phones chatting saturate the link out instantly — the arbitration in §3 is not theoretical, it is the normal case. `DUTY=0.25` loosens it for demos; `CAP=2` exercises the node-full refusal (which closes the socket *after* sending a reason, never silently).

**Then, same session — the forward flow on every tab, and it finally ran on a screen.** An emulator turned out to be available (`adb devices` → `emulator-5554`), so everything below was driven with `adb input` against a live mock, not just compiled.

- **Live** — share position · rename callsign · reset track; real people rows; node stats (uptime, `0.00% of 1.0% ceiling`, queue depth).
- **Map** — peers are real now (`peer` frames replaced `dummyPeers`), each with its own accuracy ring, age pill and staleness colour. Sharing twice in a row rendered the skip: *"1 m from your last shared position — decimating below 50 m"*.
- **Chat** — unchanged from earlier in the session, verified on-screen: bubble → `seq` → `relayed`, `382 ms airtime`.
- **Clients** — the fake meters are gone; roster, per-client airtime share, duty-cycle used and queue depth all come from a node `stats` frame every 5 s. Ghost peers are labelled `ghost · synthetic peer` so the mock can never be mistaken for a real client.
- **Config** — staged locally, written explicitly as one patch (§6). Node answers key-by-key: `decimationM` `50 → 120` staged, written, `[=] ridge-1 wrote config: {"decimationM":120}`, row updates, "LAST WRITE → applied · 120". Locked keys (`dutyPct`, `apIdleTimeoutS`, `maxClients`) render with the *reason* they are not settings rather than a greyed box.

New on the node: `src/nodestate.js` (config with locked keys, trailing-hour airtime accounting, position decimation by distance) and `--ghosts N`. 25 mock tests, 21 Kotlin tests, all green.

**Two more honesty bugs caught by actually looking at it** (the reason "compile-green" was never enough): (1) a disabled Send button with no explanation — the user asked whether it was broken, which it wasn't, but a control that refuses without saying why *is* the spinner problem in another hat; the Chat tab now names the failure and the next action, and Diagnostics shows the node URL. (2) after a successful rename, the title bar and "your callsign" still read the old name — `selfName` was only ever set from `hello`. The roster is the node's answer about who we are, so it now updates `selfName`, exactly like `seq` on a message. Same ownership rule, second instance.

**Also: no real names in this repo, ever.** The auto-assigned client names were real-sounding first names (inherited from the wireframe copy). Replaced project-wide with NATO callsigns — `alpha`, `bravo`, `charlie`, … — in code, tests, docs, HTML wireframes and the queue-reason examples. A callsign is what a field radio hands out anyway, and it reads better in "queued 56 s, bravo ahead of you". Recorded as a rule in CLAUDE.md and PROJECT.md §9.

**Third pass, same session — the first-run flow, which was missing entirely.** The app booted straight into the shell: no splash, no permissions, no onboarding, and the BLE permissions §5 specifies weren't even in the manifest. Now: launch theme paints the app's own paper (no white flash) → boot screen naming the node → four setup steps on first run only, re-enterable from Config → **Open setup again**.

The steps are *what this is · permissions · battery · the node*. Permissions requests `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` (+ `POST_NOTIFICATIONS` on 13+), each with its reason, plus an explicit **"not asked for: location — never"** row, which `neverForLocation` makes true. Battery detects `isIgnoringBatteryOptimizations` and opens the settings list — deliberately the *list*, not the `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` dialog, which needs a permission flagged sensitive that a personal build does not need. Verified on the emulator: both system dialogs fire, `dumpsys` confirms all three granted, the pills flip, relaunch skips setup.

Two judgement calls worth writing down. **(1) No fake BLE.** The whole flow asks for Bluetooth and then connects over WebSocket, which would be a lie if the UI implied otherwise — so Config carries `ble link · phase 03 · needs the board`, and the permissions step ends with "nothing connects over Bluetooth yet". The permission path is real; the link is not, and the screen says which. **(2) No `SyncService` in the manifest.** `POST_NOTIFICATIONS` is requested for the foreground service that will carry background sync, but declaring a `<service>` pointing at a class that doesn't exist is the kind of thing that works until the day something starts it. The service lands with BLE.

The node URL is now editable and persisted (`Prefs`), which retires a real trap: `10.0.2.2` is an emulator-only alias, so on a physical phone the old hard-coded default could only ever fail, and it failed looking exactly like a broken app. `MainActivity` keys the ViewModel on the URL, so changing nodes builds a new socket instead of relabelling the old one.

**Fourth pass — "rebuilt, still missing", and both halves of that were fair.** Two separate causes, neither of them a build problem:

1. **Onboarding was hidden by its own success.** `shared_prefs/lokalgrid.xml` had `onboarded=true` from the verification run, and reinstalling keeps app data — so setup correctly never showed again. Reachable via Config → *Open setup again*, or `adb shell pm clear dev.lokalgrid.app`.
2. **The splash genuinely wasn't there.** Two real defects. (a) On Android 12+ the *system* splash screen is drawn from `windowSplashScreen*` theme attributes and the launcher icon — my `windowBackground` trick is ignored there, so what actually appeared was the stock robot on a stock background. (b) **The app had no launcher icon at all** — no `ic_launcher` anywhere in `res/`, which is why the robot showed up. Fixed both: an adaptive icon whose mark is *a fix inside its accuracy rings* (the §6 rule as a logo — never a crisp dot), wired into `windowSplashScreenAnimatedIcon` for 31+ with the layer-list `windowBackground` still covering 30 and below.

And the Compose boot screen was up for exactly one frame, which is not a splash — `LaunchedEffect` routed away immediately. It now holds until the **first connection attempt resolves**, capped at a 1200 ms grace, showing the node URL and what the attempt is doing. Verified with the mock killed: it says `error: Failed to connect to /10.0.2.2:8787` and lets you in anyway — a node that is down costs a second, never the app. That is the difference between waiting on something real and padding a timer.

Onboarding has no automated test — `Setup` reads `Build`/`PackageManager`, so it needs Robolectric or an instrumented test; the Journeys harness (§6) is the intended home for that.
